# SYMBL 字符显示实现分析：REA 参考

## 结论

字符表的主要机制是 **UTF-8 编码、网站托管的字体分片、按码位选择字体类、可见单元格复用，以及特殊字符的专门处理**。主体走文本字形渲染；页面虽有 SVG 图标和 WebP Emoji 图片，不能据此说所有字符都是图片。

个人 Unicode 音型输入法最值得借鉴的是：让预览依赖明确、可验证的字体来源，并把原始字符身份、预览字形和复制内容分开管理。

“显示很多字符”不能证明“所有 Unicode 字符都在所有设备上正确显示”。本次样式只声明 U+0000–U+1FFFF 的 128 个字体选择桶；补充汉字、更高平面、新字符与组合序列仍需核验。

## 2. 编码正确与字体有字，是两个问题

HTTP 响应为 `Content-Type: text/html; charset=UTF-8`，HTML 也声明：

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

脚本使用数字字符引用和 `String.fromCodePoint` 生成字符，并保留码位标签。可读化表达为：

```js
charHtml = "&#" + renderCodePoint + ";";
copySymbol = String.fromCodePoint(renderCodePoint);
```

这能正确表达补充平面码位，但数字引用不会给字体补齐字形。

| 现象 | 原因 | 应对 |
| --- | --- | --- |
| 变成一串错误文字 | 编码解码错误 | 文件、HTTP、JSON、TSV 全链路统一 UTF-8 |
| 出现空方框或带码位方框 | 缺字或字体没加载 | 检查覆盖、网络和实际字体 |
| 不可见但码位正确 | 空格、控制、格式或零宽字符 | 单独状态标记 |
| 有字形但组合位置不对 | shaping、组合标记或变体序列 | 按完整序列验证 |

## 3. 核心：每 1,024 码位选择一个字体桶

`character-table.js` 的 `dec2font` 按下式选择字体类（等价可读化）：

```js
const start = 1024 * Math.floor(codePoint / 1024);
const fontClass = "u" + start.toString(16).padStart(4, "0");
```

`deferred-styles.css` 对应声明：

```css
@font-face {
  font-family: u13000;
  src: url("/fonts/u/u13000.woff2") format("woff2"),
       url("/fonts/u/u13000.woff") format("woff");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
.u13000 { font-family: u13000; }
```

CSS 来自 `symbl-cdn.com`，其相对字体路径也解析到该 CDN。`𓆟`（U+1319F）选择 `u13000`；`🔔`（U+1F514）选择 `u1f400`。`_changeClassLink` 移除复用节点的旧字体类，再加入新类，避免滚动后沿用上一字符的字体。

核验结果：

- 128 个字体定义，从 `u0000` 到 `u1fc00`，以 0x400 递增。
- 下载的三份 CSS 都没有 `unicode-range`；这里是脚本显式选类，不能解释成 `unicode-range` 自动分流。
- WOFF2 优先、WOFF 备选，`font-display: swap` 允许先显示替代字体；加载期间仍可能短暂缺字或变形。
- 按需字体加载有助于减少首次传输，这是基于浏览器机制的推断；没有运行时请求统计或加载时间证据。

FontTools 抽样结果：

| 文件 | 字节数 | cmap 项数 | 抽样码位 |
| --- | ---: | ---: | --- |
| u0000.woff2 | 59,248 | 1,049 | U+0041 存在 |
| u13000.woff2 | 404,992 | 1,026 | U+1319F 存在 |
| u1f400.woff2 | 383,696 | 1,027 | U+1F514 存在 |

cmap 项数不是已分配字符总数。部分字体还映射空格、替换字符等桶外码位。存在映射不等于轮廓非空、正确或排版正确，三个样本也不能代表全部字体。样本 name ID 13 没有许可证文本；公开下载地址不能代替再分发授权，项目应继续使用已确认授权的字体来源。

## 4. 流畅浏览来自窗口化渲染

HTML 含 `data-blocks-table` 区块数据，但字符列表初始为空：

```html
<ul class="character-table__list" data-character-table="table"></ul>
```

脚本按视口计算 `_countItemsOnScreen`，`mount` 仅建立这批单元格。滚动时求当前行，由 `_getSymbolsForRender` 建立 `_visibleItems`，再更新已有节点，通过 `requestAnimationFrame` 调度。桌面每行 16 格，窄屏每行 8 格；总容器高度用于提供全范围滚动空间。

这不是一次创建全部 Unicode 字符节点。窗口化改善性能和字体需求规模，不负责修复编码或缺字。本次未测量 FPS、内存或跨设备表现。

## 5. 特殊字符与复制边界

区块数据配合禁用信息，为未定义码位显示 `Not defined`，私用区显示 `For private use`。私用字符没有统一公共字形。

控制字符有替代预览：U+0000–U+001F 映射到 U+E400 起的私用码位，U+0080–U+009F 映射到 U+E480 起的私用码位。`_resolveRenderCodePoint` 求替代显示码位，渲染器记录 `data-substitute`。

值得谨慎借鉴：这个版本的 `copySymbol` 从替代后的 `renderCodePoint` 生成，且一些禁用条件会关闭它；不能承诺控制字符始终复制原始码位。桌面弹窗还有其他复制逻辑，本次未做交互验证。

项目应把原始码位/序列作为身份，“复制原文”始终取原始值；控制符图示、点圆组合预览、PUA 替代仅用于显示，不能写回码表。不要自动删除 VS16、ZWJ 或改变有意义的序列。

## 6. 对个人 Unicode 音型输入法的建议

项目已有 `工具/validate_preview_fonts.py`，会检查选定字体和嵌入分片的 cmap，也检查空白字形；[[理论/第一次字形优化交付说明]] 已记录主字体哈希、第二字体差异与渲染失败。应复用这些成果。

以下为设计参考，本次未修改编辑器、码表或 Rime：

1. 建立字体清单，记录来源、授权、版本、SHA-256、覆盖与渲染异常。1,024 码位桶不等于 Unicode 语义区块。
2. 沿用已有 Preview 分片和覆盖检查，按确切字符覆盖选择预览字体；分别补验古文字、数学字符和 CJK 补充汉字。
3. 全形编码依赖字形，人工确认保留主字体版本/哈希；争议字符允许比较第二字体，避免字体变化悄悄改变形码依据。
4. 原始字符串、预览文本和复制值分开保存；单元格复用时同步更新字体类。
5. 区分字体加载中、请求失败、没有已验证字体、字符本来不可见；不要用方框暗示字符不存在。
6. 大范围浏览可以比较现有分页与可见行复用，避免一次生成十几万个节点。
7. 验收分 cmap、真实轮廓、浏览器截图、复制回读四层；对组合标记、Emoji 序列、PUA、控制符分别测试。`document.fonts.check` 不能单独证明正确字形覆盖。

建议数据边界（不是 SYMBL 原码）：

```js
const item = {
  original: String.fromCodePoint(0x1319F),
  codePoints: [0x1319F],
  previewFontId: "verified-egyptian-font",
  previewText: String.fromCodePoint(0x1319F),
};
preview.textContent = item.previewText;
preview.style.fontFamily = fontManifest[item.previewFontId].cssFamily;
await navigator.clipboard.writeText(item.original);
```

网页字体不会随纯文本粘贴到目标应用，也不会自动成为小狼毫候选窗口的字体。网页预览、输入法候选和接收文本的应用需要分别配置验证。
