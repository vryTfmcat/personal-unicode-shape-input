# Unicode 符号拼排 · Android 0.2

### 0.2.4 空白字形与按钮文字修复（2026-10-21）

0.2.3 存在实际回归，不再推荐使用：补缺用 Essenfont 带有 CBDT／CBLC 位图表，Android 会优先采用其中空白位图，导致有轮廓、有 cmap、`hasGlyph=true` 的字符仍画成空白。由于同一字体栈还用于按钮，中文操作标签也消失。已在同一台手机通过画布复现；移除位图表后，同样的汉字可正常绘制。

0.2.4 只让候选、弹出预览和符号使用补缺字体，按钮、注释及输入文字恢复系统字体，保留键位、颜色和比例。生成器去除补缺字体位图表并断言最终文件不存在这些表；工作区测试增加界面字体隔离检查。43 份原生字体现约 70 MB，当前字符目录的映射覆盖仍为 159,345。安装包 `发布/Unicode符号拼排-0.2.4-debug.apk` 约 77 MB，部署包 `发布/Unicode-Trime-0.2.4.zip` 约 40 MB；均附 SHA256。

已在 Android 16 手机安装并完成真实绘制检测：17 个样本均有非空像素，包括中、区、空、`f` 编码首项 U+FE5D、`aa` 编码首项 U+107A8、埃及象形、楔形、音乐符号和扩展汉字。APK 内字体逐字节检查、ZIP CRC、工作区测试通过；交接目录 43 份字体 SHA256 一致。此前 0.2.3 的九项 `hasGlyph` 测试不能证明字形可见，已改成同时检查实际像素。用户已完成同步、部署、重选主题，并确认“按钮和符号都恢复了”。ADB 同时核对编译主题的按钮字体为空列表（采用系统字体）、候选字体为 43 项，以及运行目录的新轮廓字体 SHA256 一致。

### 0.2.3 同文原生字体补齐（2026-10-21）

新增 43 份原生字体回退，未压缩约 96 MB。由现有授权字体资源生成，保留许可证；字符映射覆盖当前目录的 159,345 个字符。候选、注释、键帽、预览及输入区使用同一回退列表。编辑器的固定目录发布、原生 ZIP 及浏览器 ZIP 都携带字体，浏览器导出按二进制读取，避免破坏字体文件。安装包约 102 MB，部署 ZIP 约 64 MB，位于 `发布/Unicode符号拼排-0.2.3-debug.apk`、`发布/Unicode-Trime-0.2.3.zip`。

已在本轮 Android 16 手机安装更新，测试 Android 原生字体加载：43 个字体族全部成功；`Paint.hasGlyph` 对 U+2C2D、U+1319F、U+12054、U+25CB、U+1D11E、U+20000、U+30000、U+31350、U+323B0 全部返回 true。APK 中 43 份字体与构建源逐字节一致，手机交接目录 SHA256 全部一致，APK 验签、部署 ZIP CRC 和工作区测试通过。现有键位、颜色、行高保留。字体加载检测不等于所有组合排版和视觉细节均已验收；同文同步部署后的实际候选显示待用户确认。

字体目录须整体同步，之后部署并重新应用主题。该回退机制需要 Android 10（API 29）以上；旧版系统不能保证完整覆盖。字体只作用于同文，微信等接收应用及对方设备使用各自字体，仍可能缺字。本版本替代下方 0.2 历史记录中的“同文使用默认字体”状态。

### 0.2.2 行高与功能键配色修正（2026-10-21）

用户真机确认主题修复成功。顶部模式栏与字母行不再等高：五行原始高度依次为 28／52／52／52／48，由同文按总键盘高度 270 dp（横屏 200 dp）缩放。顶部文字 14 sp，功能键文字 16 sp。左侧模式键、退格、符号与回车显式设为深绿 `#335d4a`、白字；顶部模式按钮用浅绿底，通过“关”字显示候选层状态。空格键使用独立的 `UnicodeSpace`，标签为“空格”，不再显示过长的方案名。

原因：旧生成器未给行首按键设置独立 `height`，同文会让五行等高；深绿色只配置了候选高亮，没有设置功能键的 `off_key_back_color` 及按键级颜色。修正生成器、浏览器预览和手机主题，保留已有字母按键映射及 0.2.1 方案布局绑定。新安装包与基线包为 `发布/Unicode符号拼排-0.2.2-debug.apk`、`发布/Unicode-Trime-0.2.2.zip`。已构建、验签、安装，并检查手机编译主题的行高、功能键配色及空格标签。

### 0.2.1 键盘启动入口修正（2026-10-21）

0.2.0 的主题和 Unicode 绿配色能加载，但实际软键盘会落到同文默认 qwerty，导致上方模式按钮不出现。原因已核对同文 3.3.12 `KeyboardWindow.smartMatchKeyboard()` 源码：优先采用与当前 Rime 方案 ID 同名的 preset；没有时按 alphabet 匹配 qwerty，不按 `style/keyboards` 列表第一项启动。

0.2.1 在主题增加 `preset_keyboards/personal_unicode_android/import_preset: unicode`，明确把安卓方案接到手机布局；同时更新编辑器导出器，防止下次发布撤销修正。修正手机现有文件时保留全部原有按键设置，只补启动绑定。安装包 `发布/Unicode符号拼排-0.2.1-debug.apk`，基线包 `发布/Unicode-Trime-0.2.1.zip`。已安装到本轮调试手机、更新交接目录文件。用户同步部署后确认入口出现，并提供实际键盘截图：上方中／区块／全形关／收藏关／混合，以及 Z 左侧模式⇧均正确显示；ADB 同时验证编译主题中的同名方案布局绑定。

## 手机使用顺序

1. 同文已设置的外部目录：`Documents/Unicode-Rime`。
2. 编辑器 → 草稿／发布 → 选择同文交接目录，选择同一个文件夹并授予访问。
3. 完成编辑，创建草稿快照，再点“更新交接目录中的部署文件”。也可导出 ZIP 手动解压到目录。
4. 同文执行“从外部存储同步”及“部署”，选择“Unicode 安卓三模式”和“Unicode 手机三模式”。主题的实际内部标识是 `unicode_mobile`。
5. 试输 `gltu` 检查 `Ⱝ` 候选，再测试模式循环、中英切换、退格、空格选字和直接符号键。
6. 测试成功后，回编辑器的对应发布记录，点“记录：已在同文部署并测试”。恢复旧草稿不会回退当前同文；回退也要重新更新、同步、部署。

## 构建入口补充

`prepare_assets.py` 还调用 `工具/build_trime_bundle.py`，仅将独立安卓方案生成到触屏资源；不替换电脑方案。`工具/package_trime.cjs` 可生成基线安装文件，或接收编辑器备份路径打包。`工具/test_touch_workspace.cjs`、`工具/test_trime_native.py` 分别验证草稿／导出和独立 Rime 运行逻辑。

以下保留第一版实现和验证记录，设备状态以本轮实际检查为准。

Android 8.0（API 26）以上；建议保持 Android System WebView 更新。手机和平板共用触屏界面，支持横竖屏。调试安装包在 `发布/Unicode符号拼排-0.1.0-debug.apk`。

APK 包含本地字符快照、现有字体和两套键盘外形，不需要连接电脑或网络。布局保存在本应用内，可通过 Android 文件选择器导入导出 JSON。复制通过系统剪贴板完成。未申请网络、存储目录、麦克风或通讯录权限，不需要授予整个文件目录的访问权。

这是符号浏览、布局编辑和应用内试输工具。尚未实现 Android 系统输入法服务，不能直接在其他应用中作为输入法弹出；目前通过复制使用符号。没有跨设备同步，也没有发布到应用商店。

## 构建

需要 JDK 17、Android SDK 35、Gradle 8.9 和 Python 3。仓库带 Gradle wrapper，Android 插件固定为 8.7.3。

1. 在本机 `local.properties` 设置 `sdk.dir`。该文件不提交 Git。
2. 将 `JAVA_HOME` 指向 JDK 17。
3. 在本目录运行 `./gradlew.bat assembleDebug`（Windows）或 `sh ./gradlew assembleDebug`（Mac/Linux）。

`prepare_assets.py` 在构建前调用 `工具/build_touch_data.py`，从现有码本生成只读快照，仅复制触屏界面、KLE 核心、KLE 几何、字体和许可证。不打包个人笔记、原件路径、历史任务、服务器数据或其他编辑器界面。生成目录 `generated-assets/` 和构建产物不进入 Git。

本地静态资源以 `https://appassets.androidplatform.net/assets/` 为固定来源，通过 WebView 请求拦截读取 APK 内资产；禁止 file/content 访问和外部导航。Android 官方对本地资源来源的说明：[Load in-app content](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)。文件读写使用系统文档选择器，只有用户选中的文件可读写。
